# 封闭池塘标记重捕估算系统

第二轮调查有些鱼的标记号看不清：先按两轮独立抽样估出鱼数范围，再决定要不要补查。
Flask + SQLite 单页应用，支持 `docker compose` 一键启动。

## 功能

- **上传两轮 CSV**（各 1～300 条）：
  - 首轮：表头 `tag`，每行一个放回鱼的**唯一标记号**；
  - 次轮：表头 `sample_no,status,candidates`，每行填唯一样本号、标记状态
    （`有标` / `无标` / `看不清`）和来自首轮的候选标记号（`;` 分隔，可空）。
- **配对规则**：有标必配、无标不配、看不清可配可不配、每个首轮标记只用一次。
  用二分图匹配（Hopcroft-Karp）求：
  - **最少重捕数** = 覆盖全部有标样本的匹配（附一套配对）；
  - **最多重捕数** = 在此基础上让"看不清"样本尽量增广（附一套配对）。
- **鱼数估算**：`N = 首轮条数 × 次轮条数 ÷ 重捕数`，按最少/最多重捕给出估算两端；
  重捕数为 0 的端点标为**不可估**。
- **逐条更正**：网页上每条次轮记录带**版号**，按所见版号提交更正（乐观锁），
  成功当次显示并保存新估算，版号 +1。
- **无解证明**：若无法覆盖全部有标样本，按霍尔定理给出一组有标样本及其候选号并集，
  证明"不同候选号 < 样本数"。
- **失败保护**：过期（版号不符）、无解或写入失败时，本次修改不生效，
  上次记录与估算原样保留；数据存于 SQLite 文件，**重启后仍可查看**。
- **外部复算包**（请外部团队复算最大重捕数，现场标记号/样本号不出站）：
  - 首页一键把**当前调查**下载为 JSON 复算包：包内只有**包号**和两轮记录，
    首轮标记号、次轮样本号与候选标记号全部换成**包内代号**（代号带包号派生前缀，
    次序经密码学随机源打乱），次轮状态与候选关系照录；**每次发包都用新代号**。
  - 发包同时在库内留存**代号↔原号对应表**与核验依据（发包时的两轮记录、最大重捕数、
    与下载逐字节一致的包文件）；留存与下载取自同一已提交状态，**留存失败不给下载**。
  - 复算方交回含 `package_no` 与配对清单 `pairs` 的 JSON，首页上传后**当次给出结论**：
    只收本包代号，按发包时的记录核对**有标必配、无标不配、候选关系、样本与标记各只用一次**；
    **任一合法的最大配对都算通过**。
  - 配对合法但还能多配时，列出**增配一对**须撤掉和补上的配对；核验不通过时逐条说明原因。
    可定位的记录与换配步骤一律用**本站原号**显示。
  - 核验只读留存数据，**不改调查记录和估算**；重新导入调查或重启后，**旧包仍可核验**。

## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问 http://localhost:8000 。SQLite 数据库保存在命名卷 `appdata` 中，容器重建不丢数据。

### 本地运行

```bash
pip install -r requirements.txt
python app.py            # 默认 0.0.0.0:8000，DB 为 ./markrecap.db
```

环境变量：`DB_PATH`（数据库路径）、`PORT`（端口）、`SECRET_KEY`（会话密钥）。

## CSV 格式

`examples/round1.csv`：

```csv
tag
T01
T02
```

`examples/round2.csv`：

```csv
sample_no,status,candidates
s01,有标,T01
s02,有标,T02;T03
s07,无标,
s13,看不清,T10;T11
```

- 编码 UTF-8（可带 BOM）；候选号可用 `;` `；` `|` `/` `、` `,` 或空格分隔。
- 表头支持中文别名：`标记号` / `样本号` / `状态` / `候选号`。
- 候选号必须来自首轮；`无标` 行不得填写候选号。

## 外部复算包 JSON 格式

下载的复算包（文件名 `recap_package_<包号>.json`）只含包号与换号后的两轮记录，
**不含任何现场原号**：

```json
{
  "package_no": "RP-HUZTNAND",
  "round1": [
    {"tag": "TAG-HUZT-001"},
    {"tag": "TAG-HUZT-002"}
  ],
  "round2": [
    {"sample_no": "SMP-HUZT-001", "status": "有标", "candidates": ["TAG-HUZT-002"]},
    {"sample_no": "SMP-HUZT-002", "status": "无标", "candidates": []},
    {"sample_no": "SMP-HUZT-003", "status": "看不清", "candidates": ["TAG-HUZT-001", "TAG-HUZT-002"]}
  ]
}
```

复算方交回的文件顶层为 `package_no` 与 `pairs`，配对中的代号必须取自该包：

```json
{
  "package_no": "RP-HUZTNAND",
  "pairs": [
    {"sample_no": "SMP-HUZT-001", "tag": "TAG-HUZT-002"},
    {"sample_no": "SMP-HUZT-003", "tag": "TAG-HUZT-001"}
  ]
}
```

核验结论（HTTP 200 通过 / 422 未通过或可增配 / 400 格式错误 / 404 包号未留存）直接渲染在首页，
所有可定位的样本号、标记号与换配步骤均换算回本站原号。
